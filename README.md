# Stylo

Stylo сравнивает авторскую манеру русской прозы: синтаксис, пунктуацию, служебные слова и
последовательности языковых признаков. Он оценивает методы на отложенных произведениях
и строит отдельный отчёт для выбранной книги.

[Статья](https://stylometry.russkiykod.com/) · [Методика](docs/runbooks/stylometry.md) · [План](research/ROADMAP.md)

## Установка

Из корня проекта:

```bash
uv venv --python 3.11 --seed
uv pip install --constraint requirements.lock -e ".[dev]"
.venv/bin/python -m spacy download ru_core_news_lg
```

Проверенное окружение — CPython 3.11 на Linux. Модель spaCy устанавливается отдельно;
`--seed` добавляет нужный её загрузчику pip. Установленный wheel также поддерживает обучение:
Git для обычного расчёта не нужен. Raw-тексты вместе с проектом не распространяются.

## От корпуса до отчёта

Положите UTF-8 тексты в `input/<author_id>/<work_id>.txt`: одно произведение в одном файле.
Исследуемый текст — например, `input/unknown/target.txt`. Подготовьте короткий конфиг
`research/local/case.yaml`; неперечисленные поля берутся из настроек по умолчанию:

```yaml
deployment:
  candidate_authors: [author_a, author_b]
evaluation:
  training_weighting: work_balanced
paths:
  data: research/local/case/data
  docs: research/local/case/results
```

Замените `author_a` и `author_b` именами каталогов эталонных авторов и выполните:

```bash
.venv/bin/stylo analyze --config research/local/case.yaml --target-work unknown/target
```

Команда очищает и проверяет корпус, откладывает выбранное произведение, нарезает тексты,
обучает модели и создаёт JSON/HTML-отчёт в каталоге результатов. LR и Delta показываются отдельно.
Выбор цели явный: соседние книги из `unknown` не смешиваются в один ответ. Другие издания
исследуемой книги и сборники с тем же содержанием также должны быть исключены из эталонов:
обнаруженное пересечение выбранной цели с эталонами останавливает `analyze` до обучения.

Для повторного анализа подготовленных данных есть отдельные `clean`, `validate-corpus`, `split`,
`train`, `predict` и `report`; параметры перечислены в `stylo <команда> --help`.
При отдельном `predict` модель выбирается по `bundle_token` из результата `train`;
`analyze` передаёт этот идентификатор автоматически. Оценки внутри панели не являются вероятностями авторства.
Пути в конфиге разрешаются относительно рабочего каталога запуска.

Каждый результат сохраняется отдельной полной версией: новая модель или другое оформление
не заменяют прежний отчёт. Команда выводит путь к HTML и `result_id`. Сохранённую версию можно
проверить повторно и получить путь к HTML, указав полный идентификатор:

```bash
.venv/bin/stylo report --config research/local/case.yaml --result-id <result_id>
```

Достаточно того же каталога результатов; исходные тексты и прежний конфиг для чтения выбранной
версии не требуются. `evaluation.top_k_candidates` и `paths.docs` можно менять для нового
`predict` с уже обученной моделью. Признаки, панель кандидатов и настройки обучения остаются
привязаны к модели.

## Проверить на синтетическом примере

```bash
.venv/bin/python scripts/make_demo_corpus.py --output research/local/demo
.venv/bin/stylo analyze --config research/local/demo/case.yaml --target-work unknown/target_periodic
```

Пример создаёт оригинальные синтетические тексты двух вымышленных авторов и две цели. Он проверяет
рабочий путь, а не точность на литературе. Генератор требует новую директорию и не перезаписывает файлы.
Очистка хранит полные поколения в `*.snapshots/`; старые данные автоматически не удаляются.

## Что измерено

В завершённом сравнении на исправленном корпусе вариант A4 верно распознал **225 из 248 произведений
(90,73%)** с обоими наборами признаков; A0 — 216 и 218. A4 меняет веса обучения, обучение словаря
и нормировку частот. Это качество распознавания известных авторов на данной проверке, а не результат
атрибуции «Двенадцати стульев» или «Тихого Дона». [Источник и условия](research/evidence/topic_validity_lobo_v1/aggregate.json).

Прежние расчёты на исходном корпусе сохранены как исторические: в нём были пересечения содержания,
интервал macro-F1 отозван. [Регистрация корпуса](research/evidence/ineligible_corpus_registrations_v1.json),
[пояснение к интервалу](docs/macro_f1_ci_withdrawal.json), [статус измерений](research/governance/status_ledger.json).

## Разработка

```bash
.venv/bin/python -m pytest tests -q -p no:cacheprovider
cd site
npm ci --no-audit --no-fund
npm run gen
npm run build
```

`src/stylo/` — библиотека и CLI; `configs/` — настройки; `tests/` — проверки;
`scripts/` — исследовательские запуски и генератор данных сайта; `site/` — статья.
`docs/*.json` и `research/evidence/` содержат источники графиков и результаты.
Локальные журналы, модели, кэши и корпуса в Git не входят.

Код — MIT. Исходные тексты имеют собственные условия использования и вместе с кодом не распространяются.

# Ревью Stylo и исследовательские приоритеты

## Запрос и границы

- Дата: 2026-10-02.
- Владелец запросил комплексное ревью кодовой базы, исследование повышения точности,
  дополнительных источников и методов поиска иного авторства.
- Уточнённые кейсы: Булгаков и «Двенадцать стульев»; Шолохов и «Тихий Дон».
- Проверяемый baseline: `f312efb8f5fa291a961c337e6efa3b67cc247be4`; дерево в начале чистое.
- Handoff ссылается на предшествующий `25156bf`; текущее состояние проверяется по коду,
  governance и выполняемым проверкам.
- Работа: анализ исходников, агрегированных артефактов, синтетические проверки, тесты,
  поиск первичной научной литературы. Изменения реализации, реальные корпусные fits,
  публикация и внешние записи не входят в это ревью.
- Приватные тексты и секреты не читаются и не включаются в отчёт.

## Результат

Ревью завершено. Реализация не изменялась. Ниже — проверенные дефекты, научные ограничения
и предложения для следующей работы; они не заменяют нормативный `research/ROADMAP.md`.

Stylo имеет серьёзную инфраструктуру воспроизводимости, но пока не имеет измеренной текущей
точности на исправленном корпусе и завершённой процедуры открытой авторской верификации.
Поэтому увеличение числа моделей само по себе не приблизит доказательство чужого авторства.
Приоритет: исправить измерительные ошибки, обеспечить независимость эталонов, измерить риск
ложной атрибуции, затем сравнивать методы и исследовать исторические романы.

## 1. Проверенные проблемы

P1 означает «устранить до использования соответствующего пути для научного вывода»;
P2 — существенная доработка конкретного сценария. Это приоритеты ревью, не новые записи
governance. Ни один найденный дефект сам по себе не устанавливает авторство произведений.

### R1. P1: штатный train/predict не подходит для двух выбранных кейсов

**Факт и источник.** `src/stylo/resources/default.yaml:145` исключает `ilf-petrov` и
`sholohov` из benchmark. `src/stylo/pipeline/train.py:125` использует тот же список для
обучения deployment-модели. `src/stylo/pipeline/predict.py:136` ранжирует оставшихся авторов,
а `:151` всегда печатает победителя. Низкий margin лишь добавляет предупреждение (`:153`).

**Интерпретация.** На стандартной конфигурации модель не сможет выбрать Ильфа–Петрова или
Шолохова. Чужой победитель в таком опыте предопределён составом панели. Это ограничение
штатного пути, а не доказательство такой ошибки в специализированных исторических прогонах.

**Следствие.** Разделить benchmark exclusion и явно заданную case candidate panel. Возвращать
диагностический рейтинг отдельно от решения о применимости. Ввести проверенный ответ
«автор вне панели / недостаточно данных». Case framework уже правильно воздерживается:
`src/stylo/cases/framework.py:938` и `:1794` указывают на отсутствующий calibrated open-set
gate и возвращают `top=None`, `abstained=True`. Это сознательно незавершённая возможность.

### R2. P1: validator объявляет почти разные тексты дубликатами

**Факт и источник.** `src/stylo/corpus_tools/validate_corpus.py:153` использует 4–5-словные
TF-IDF n-граммы с `min_df=2`. Уникальные части документов исключаются из пространства
сравнения; остаётся только общее. Высокий cosine у разных авторов становится `error` (`:163`).

**Воспроизведение.** Два синтетических текста по 605 слов, совпадают только первые пять,
остальные 600 различны: cosine `1.0000000000000002`, `errors=['near_dup']`. Два текста
без общих 4–5-грамм: необработанный `ValueError: After pruning, no terms remain`.

**Следствие.** Общий короткий эпиграф способен заблокировать полноценные разные произведения.
Считать совпадение относительно полного объёма shingles, отдельно обрабатывать отсутствие
общих признаков, подтверждать дубли длиной/покрытием совпадающих участков. Этот дефект относится
к указанному validator; он не доказывает отказ всех дополнительных content-isolation gates.

### R3. P1: неверный интервал macro-F1 в invariance

**Факт и источник.** `src/stylo/eval/invariance.py:754` выбирает работы с возвращением,
но вычисляет F1 по неизменному глобальному набору классов (`:758`). Автор, случайно
не попавший в bootstrap-выборку, получает F1=0 (`:625`).

**Воспроизведение.** 20 авторов, по две работы, два источника, все предсказания правильные:
общий macro-F1 `1.0`, CI `[0.75,1.0]`; в каждом source-срезе macro-F1 `1.0`,
CI `[0.5,0.75125]`. Последний интервал целиком ниже безошибочной точечной оценки.

**Следствие.** Интервалы этого пути нельзя использовать как меру научной уверенности.
До выбора корректного estimand разумно оставлять точечный F1 без CI. Затем реализовать
соответствующий дизайн resampling. Простое удаление отсутствующих классов тоже меняет
оцениваемую величину и требует обоснования. Существующий отзыв исторического macro-F1 CI
не закрывает этот отдельный вычислительный путь.

### R4. P2: смешанное произведение считается одноавторским контролем

**Факт и источник.** `src/stylo/eval/segmentation.py:843` проверяет одноавторство отдельного
документа, после чего добавляет его `work_id` к контрольным произведениям (`:855`, `:888`).
Объединение truth-авторов всех документов произведения не проверяется.

**Воспроизведение.** Глава A написана автором a, глава B — b, у них один `work_id`.
Идеальные предсказания дают `n_single_author_control_works=1`, FPR=0, CI `[0,0]`, хотя
одноавторских произведений в примере нет.

**Следствие.** При оценке по главам смешанная книга разбавляет знаменатель отрицательного
контроля. Сначала определять одноавторские произведения по всей truth-разметке, затем
агрегировать ошибки. Это особенно существенно для исследования частичного соавторства.

### R5. P2: clean/split может неверно описывать происхождение preprocessing

**Факт и источник.** `src/stylo/pipeline/clean.py:266` сохраняет хеши файлов, но не resolved
identity использованной модели очистки. `src/stylo/pipeline/split.py:344` читает clean-тексты,
не проверяя clean manifest; `src/stylo/workdoc.py:136` берёт masking model/version из текущей
конфигурации.

**Воспроизведение.** Настоящий `clean` с подставленной синтетической NER-моделью A, затем
смена конфигурации на B и настоящий `split`: split успешно записывает hash B. Clean manifest
содержит только `files`, `schema_version`, `source_root`. A и B здесь тестовые идентификаторы;
эксперимент проверяет связь метаданных, а не качество NER.

**Следствие.** Целостность байтов не гарантирует верное описание их обработки. Записывать
actual resolved NER identity, параметры и версию cleaner; split должен проверять эту цепочку.

### R6. P2: embedding cache смешивает разные настройки

**Факт и источник.** `src/stylo/features/embeddings.py:62` хеширует только model name и текст,
хотя `:83` использует `max_length`. Загрузка весов (`:55`) не закрепляет revision.

**Воспроизведение.** После записи вектора при `max_length=256` новый блок с `512` читает
тот же вектор и не вызывает encoder.

**Следствие.** Эксперименты с длиной контекста могут фактически использовать старые признаки.
В ключ должны входить revision весов/tokenizer, max_length, pooling и нормализация; нужны
проверки размерности и конечности вектора. Этот экспериментальный блок выключен по умолчанию;
влияние данного дефекта на основной Stylo не утверждается.

### R7. P2: pin bundle token через config ломает обещанный сценарий

**Факт и источник.** CLI обещает config pin (`src/stylo/cli.py:63`), predict его читает
(`src/stylo/pipeline/predict.py:65`). Но training hash включает весь config
(`src/stylo/pipeline/train.py:113`), а publication требует его точного совпадения
(`src/stylo/report/evidence.py:258`).

**Воспроизведение.** Добавление `deployment.expected_bundle_token` после обучения меняет
config hash; `publish_prediction` падает с `SectionEvidenceError` о несовпадении конфигурации.

**Следствие.** Разделить конфигурацию обучения и параметры использования артефакта.
Текущий обход — `--model-bundle-token`, который не изменяет config.

### R8. P2: короткий хвост обходится с min_size как полноценное окно

**Факт и источник.** Условие `src/stylo/chunking.py:48` допускает любое одно предложение
с положительной длиной. Синтетические предложения длиной 500 и 1 при `min_size=200`
дают чанки `[500,1]`. `src/stylo/pipeline/predict.py:117` затем усредняет окна с одинаковым весом.

**Следствие.** Однословный хвост способен получить такой же вес, как 500-словное окно.
Предусмотреть явную политику коротких хвостов: объединение, отказ или обоснованный вес.
Отдельно синтетически обнаружена потеря символов в `split_text_safe` при длинном участке
без пробелов (`src/stylo/chunking.py:74`); это менее типичный сценарий для обычной прозы.

### R9. P2: часть подачи результатов сильнее, чем проверяемое evidence

**Факт и источник.** `site/src/segdata.js:24` задаёт `nSegments: 0` литералом;
`scripts/gen-site-data.mjs:4` прямо поясняет, что JSON этого отдельного прогона не сохранён.
Сайт использует это число в выводе об отсутствии булгаковских сегментов. Проверка provenance
сгенерированных JSON не проверяет этот отдельный литерал.

`site/src/sections/IlfPetrov.jsx:135` трактует край шкалы как «1 — точно дуэт»; ансамблевый
score сам по себе не является вероятностью исторического авторства. На `:162` второй роман
назван независимой проверкой, хотя независимость ошибок, референсов и процедуры не установлена.
Существующая общая оговорка `ResearchUpdate` полезна, но не решает эти локальные проблемы.

**Следствие.** Для будущего публичного обновления каждому утверждению нужен сохранённый
артефакт с estimand, единицей наблюдения, статусом и ограничениями. Неизвестное значение
не заменять нулём. Сайт в этом ревью не менялся.

**Дополнительно.** `src/stylo/eval/sweep.py:298` отмечает raw McNemar `p<0.05` звёздочкой
при нескольких абляциях и зависимых книгах одного автора. Это exploratory path, не доказанная
ошибка confirmatory headline. Для научного решения нужны заранее определённые семейство
сравнений и cluster-aware процедура, а не выбор удачной звёздочки.

## 2. Что уже сделано хорошо и где инженерный предел

- Реестр v3.2 не позволяет подменять готовность наличием реализации: production registry пуст
  (`src/stylo/eval/paired_audit/run_plan.py:128`), ledger фиксирует отсутствующий confirmatory run.
- Проверки fold/content/work identity и полного набора классов предшествуют обучению
  (`src/stylo/eval/paired_audit/evaluator_v3_2.py:318`). Есть строгий контракт вероятностей.
- Атомарные fragment snapshots и deployment bundle, хеширование точных байтов перед
  десериализацией, проверка runtime, work-balanced признаки и loss — полезные основания.
- Попарные сравнения проверяют одинаковые folds; generic final сохраняет направление разности
  (`src/stylo/eval/final.py:199`). Есть factor×work splits и запрет truth-fitted перестановки
  меток для именованной атрибуции сегментов.
- Модели Delta, cosine Delta, char n-граммы, BoW-LR, POS/синтаксис и experimental ruBERT уже есть.
  «Добавить Delta или BERT» без уточнения нового эксперимента — не содержательное улучшение.

Состав baseline: 113 файлов `src/stylo` / 44 070 строк, 57 scripts / 13 136 строк,
75 tests / 24 894 строки. Все 245 Python-файлов разобраны AST. Это не построчное ревью
каждой строки. Углублённо проверены corpus/clean/split, признаки/cache, train/predict,
invariance/segmentation, case framework, основные evaluator/provenance contracts и сайт
двух выбранных кейсов. Реальные raw corpora, все источники цифр сайта и внешняя безопасность
зависимостей полностью не аудировались.

Большие модули (`wikisource_vnext.py` 3132 строки, `framework.py` 1931,
`provenance.py` 1713) усложняют проверку. Однако общий рефакторинг сейчас уступает по ценности
исправлению конкретных контрактов и измерению качества. При следующих изменениях разумны:
единая семантика ranking/verification/abstention; отдельные training/inference configs;
сквозной preprocessing receipt; версия семантики кэша; тесты научных свойств, а не только
схем. В performance сначала профилировать folds и безопасно повторно использовать только
детерминированные, не обученные на test признаки. Vocabulary/IDF/scalers нельзя кэшировать
поперёк fold так, чтобы они видели held-out работы.

## 3. Почему нынешние цифры не являются оценкой точности для этих задач

`README.md:12` и `research/governance/status_ledger.json` фиксируют перекрытие содержания
между произведениями исторического корпуса. Новый corrected-LOBO результат не опубликован.
Topic study содержит 248 folds × A0/A4 × current/topic_strict = 992 fits; ledger сообщает
об остановке на 260/992 и отсутствии агрегата. В этом ревью результат заново не измерялся.

Функциональный блок с названием function_words в режиме `mfw` выбирает частотные слова,
включая содержательные (`src/stylo/features/function_words.py:105`). Синтетическое обнаружение
topic sensitivity уже зафиксировано в `docs/tasks/2026-08-23-stylo-topic-validity-gate.md`.
Величина эффекта на исправленном реальном корпусе остаётся неизвестной. `topic_strict`
уменьшает конкретную зависимость, но не доказывает полную независимость от темы/жанра.

Нужно различать четыре результата: закрытая атрибуция выбирает лучшего из списка;
верификация проверяет совместимость с автором; open-set допускает неизвестного автора;
сегментация ищет локальные изменения. Последние могут возникать от диалога, темы, времени
написания, редакции и цитат. Переход от одной задачи к другой требует отдельной проверки.

## 4. Два исследовательских кейса

### Булгаков и «Двенадцать стульев»

Исторический `docs/ilfpetrov_timeline.json` содержит 208 окон, долю к дуэту `0.63`,
к Булгакову `0.014`. Это зарегистрированные старые назначения окон, не вероятность авторства
и не измеренный процент участия. `docs/ilf_vs_petrov.json` прямо отмечает смешение автора
и жанра: Ильф представлен записными книжками, Петров — публицистикой/мемуаром.

Найден внешний ориентир: Ryabko/Savina (2021) получили LZMA-методом 57/64 назначений
блоков Ильфу–Петрову и 7/64 Булгакову. Публикация не даёт достаточного точного манифеста
референсов для проверки исключения дилогии; её следует воспроизводить, а не принимать
как окончательное доказательство. Блоки не равны независимым книгам.
[Первичная статья](https://pmc.ncbi.nlm.nih.gov/articles/PMC8534409/).

Конкретное пополнение: ранние сольные рассказы и фельетоны Ильфа и Петрова, совместные
произведения вне обеих книг дилогии, сопоставимые по периоду и регистру произведения Булгакова,
сатира современников. Тарасова (2020) документирует ранние сольные тексты и их связи с романами;
это помогает составить библиографию. Повторно использованные пассажи нужно связывать одной
content-группой или исключать из независимых эталонов.
[Статья и библиография](https://www.philology.nsc.ru/journals/sis/article.php?id=264).

Сравнивать гипотезы полного авторства Булгакова, традиционного соавторства, локального участия,
редактуры/влияния и неизвестного автора. Смесь сольных профилей Ильфа и Петрова не обязана
быть профилем их совместной работы. Если проверяется вся дилогия, «Золотой телёнок» не может
служить бесспорным эталоном «Двенадцати стульев». Обе книги исключаются из fit и настройки.

### «Тихий Дон» и Шолохов

Исторический `docs/sholokhov_rigor12.json` уже показывает зависимость результата от референса
и тома; `site/src/sections/Sholokhov.jsx` содержит оговорку о замкнутости авторских меток.
Исключить проверяемый роман из обучения необходимо, но недостаточно для доказательства
личности автора опорных произведений.

Великанова/Орехов (2019) анализировали роман вместе с «Донскими рассказами» и современниками.
Маслинский (2022) повторил исследование: результат поддерживает общего автора рассказов и
I–III томов, не поддерживает альтернативы Крюкова/Севского/Серафимовича, но не даёт достаточных
оснований для столь же уверенной атрибуции IV тома. Это содержательная точка для исследования
устойчивости, а не положительное свидетельство другого автора IV тома.
[Исследование 2019](https://publications.hse.ru/pubs/share/direct/314793949.pdf),
[повторный анализ 2022](https://ruslitras.ru/s013160950018902-6-1/?version_id=93851).

Нужны отдельные панели ранних рассказов, поздней прозы, донских современников и жанровых
контролей; расширение независимых произведений Крюкова и других кандидатов; учёт изданий,
редакций и редакторов. Все четыре тома держать вне обучения одновременно. Поздняя проза
не должна быть единственным эталоном раннего романа. Если исходная гипотеза оспаривает
и «Донские рассказы», сходство с ними устанавливает отношение между текстами, но не фамилию.
ФЭБ перечисляет научные издания, письма и факсимиле; это полезный исходный каталог для
текстологической сверки, а не автоматически однородный корпус.
[Описание ЭНИ «Шолохов»](https://feb-web.ru/feb/sholokh/rub1.html?cmd=1).

### Что добирать в первую очередь

В историческом `docs/corpus_manifest.json:4` — 51 автор, 290 файлов, известный источник

## 5. Методы и критерии полезного улучшения

Это предлагаемые эксперименты; прирост точности по ним не измерен.

| Приоритет | Эксперимент | Практический результат | Ограничение |
|---|---|---|---|
| 1 | current против уже реализованного topic_strict на corrected folds | Измерить изменение качества и ранжирования при отключении выбранных признаков | Абляция нескольких блоков не выделяет причинную долю темы; не оптимизировать по спорным романам |
| 2 | Верификация/open-set на полностью новых авторах | Измеренная ложная атрибуция, чувствительность и доля отказов | Нужны независимые данные для настройки порогов |
| 3 | General Imposters поверх Delta/char/POS | Сравнение кандидата с подходящими авторами-фоном при подвыборках | Победы в повторах не равны posterior probability |
| 4 | LZMA-репликация и отдельно PPM | Другая семья признаков и сопоставимость с опубликованными опытами | Цитаты, порядок и объём референса, редакция сильно влияют |
| 5 | Source/edition/period/genre stress tests, text distortion | Проверка, переживает ли авторский сигнал устранение побочных подсказок | Удаление содержательного сигнала может ухудшить и полезное различение |
| 6 | Локализация изменения стиля и контролируемых вставок | Мощность обнаружения по длине/доле вставки и ложные границы на целой книге | Синтетическая склейка не моделирует полноценное соавторство |
| 7 | Русский contrastive style encoder | Проверка переноса на новых авторов и произведения | Высокая стоимость, возможное попадание классики в предобучение |

PAN 2021 даёт полезную постановку верификации на новых авторах и темах, а также PPM baseline;
перенос результатов англоязычного fanfiction на историческую русскую прозу нужно измерять
отдельно. [Официальный протокол PAN](https://pan.webis.de/clef21/pan21-web/author-identification.html).
General Imposters имеет опубликованную основу:
[Seidman, 2013](https://cris.biu.ac.il/en/publications/authorship-verification-using-the-impostors-method-notebook-for-p/).

Text distortion и topic-confusion дают способы проверять смешение стиля с содержанием:
[Stamatatos, 2017](https://aclanthology.org/E17-1107/),
[Altakrori et al., 2021](https://aclanthology.org/2021.findings-emnlp.359/).
Mean-pooled ruBERT в проекте не является encoder, специально обученным авторскому стилю.
Для следующего уровня есть LUAR и contrastive обучение с тематически близкими отрицательными
парами. Их эффективность именно на выбранных русских романах неизвестна:
[LUAR, 2021](https://aclanthology.org/2021.emnlp-main.70/),
[Huertas-Tato et al., препринт 2024](https://arxiv.org/abs/2411.18472).

Главная целевая метрика для поиска чужого авторства — частота ложного принятия неправильного
автора при зафиксированном пороге. Дополнительно: чувствительность, калибровка, risk/coverage
при отказах, разрезы по жанру/эпохе/изданию, устойчивость выбора кандидата. Обычную accuracy
сохранять как вспомогательную метрику корректно заданной закрытой задачи.

Ноль ложных срабатываний на нескольких контролях не означает нулевой риск. Например, при
20 независимых одинаково распределённых контрольных испытаниях и нуле ошибок точная
односторонняя 95%-граница составляет `1 - 0.05**(1/20) ≈ 13.9%`. Для границы около 1%
при тех же предположениях требуется около 299 испытаний без ошибки. Это арифметическая
иллюстрация требуемой информации, не требование добрать 299 глав: зависимые окна и работы
одного автора не создают столько независимых испытаний.

## 6. Предлагаемая последовательность работы

1. **Исправить R1–R8 небольшими отдельными изменениями.** Критерий: воспроизведения ниже
   становятся корректными, обычный regression проходит; неподдерживаемые CI/attribution
   не представляются как научные решения. Не изменять immutable historical artifacts.
2. **Довести измерение topic validity.** Сначала проверить совместимость checkpoint/source
   bindings; выполнить существующий scoped runner и получить проверяемый агрегат.
   Оценки 26.4/32 часов из ledger относятся к старой машине/замеру, не прогноз этого ревью.
   Выбор сокращённой exploratory A0-проверки и полный A0/A4 отвечают разным объёмам вопроса.
3. **Параллельно собрать metadata census двух case panels.** Устранить неизвестные источники,
   отделить издания от произведений, согласовать независимость референсов. Критерий:
   прозрачная таблица «кандидат × произведение × период × жанр × издание × статус» и
   отсутствие target/content overlap. Больше уникальных произведений полезнее новых нарезок.
4. **Сделать development benchmark верификации.** Пары same-author из разных произведений;
   разные авторы при сходной теме; целые авторы, отсутствующие в настройке; варианты изданий;
   известные коллаборации/имитации отдельно от синтетических вставок. Обучаемые преобразования
   и калибровка выполняются только внутри соответствующих train folds.
5. **Сравнить ограниченный заранее объявленный набор методов.** Например, текущий/strict Stylo,
   cosine Delta, char baseline, LZMA/PPM и Imposters. Повторное использование тех же тестовых
   работ для выбора параметров не считать внешней валидацией. Нейросеть добавлять после того,
   как есть надёжная база сравнения и причина ожидать дополнительную информацию.
6. **Зафиксировать весь процесс поиска.** Панели, признаки, длины окон, преобразования,
   пороги, методы, семейство глав/томов/гипотез и правила неопределённости — до следующего
   просмотра target scores. Для локализации оценивать вероятность хотя бы одной ложной
   находки на всей контрольной книге; не выбирать самый удачный p-value из сотен окон.
7. **Применить к двум романам и независимо повторить.** Они уже изучались и не станут
   слепым test set задним числом (`research/protocol_v1.yaml:129`). Независимую внешнюю
   проверку организовать на новых произведениях/авторах по заранее определённому протоколу.
   Другие редакции уже изученных произведений проверяют устойчивость к изданию и не заменяют
   внешнюю репликацию. Искать текстологическое/архивное подтверждение
   устойчивых локальных находок, а не умножать коррелирующие модельные вероятности.

Возможная научная новизна: верификация русской прозы, которая измеренно сохраняет низкую
ложную атрибуцию при смене темы/эпохи/издания и обнаруживает ограниченный чужой вклад при
заранее измеренной мощности. Обнаружение конкретного неизвестного авторства остаётся
возможным исходом, но имеющиеся данные не позволяют обещать его или оценить вероятность.
Отрицательный результат по Булгакову/альтернативам Шолохову тоже должен быть допустим.

### R2: false duplicate и пустое пересечение

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from stylo.corpus_tools.validate_corpus import validate

with TemporaryDirectory() as root:
    for shared in (False, True):
        corpus = Path(root) / str(shared)
        for author, prefix in [('alpha', 'яблоко'), ('beta', 'дерево')]:
            directory = corpus / author
            directory.mkdir(parents=True)
            intro = 'Первое второе третье четвертое пятое. ' if shared else ''
            text = intro + ' '.join(prefix + str(i) for i in range(600))
            (directory / 'work.txt').write_text(text, encoding='utf-8')
        try:
            result = validate(corpus)
            print(shared, result.duplicates, [f.code for f in result.errors])
        except ValueError as error:
            print(shared, type(error).__name__, str(error))
```

### R3–R4: научные метрики

```python
from stylo.eval.invariance import evaluate_predictions
from stylo.eval.segmentation import SegmentationDocument, LabeledSpan, evaluate_corpus

y = [f'a{i}' for i in range(20) for _ in range(2)]
meta = {'author': y, 'work': [f'w{i}' for i in range(40)], 'source': ['s1', 's2'] * 20}
r = evaluate_predictions(y, y, meta, factors=('source',), bootstrap_iters=1000, seed=42)
print(r.overall.macro_f1)
print([(s.level, s.metrics.macro_f1) for s in r.factors['source'].slices])

a = (LabeledSpan(0, 10, 'a'),)
b = (LabeledSpan(0, 10, 'b'),)
r = evaluate_corpus([
    SegmentationDocument('chapter_1', a, a, 'mixed_work'),
    SegmentationDocument('chapter_2', b, b, 'mixed_work'),
], bootstrap_unit='work', bootstrap_iters=20)
print(r.aggregate.n_single_author_control_works,
      r.aggregate.single_author_work_false_positive_rate)
```

### R5: подмена identity очистки последующим config

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import json
import spacy
from stylo.config import load_config, with_overrides
from stylo.pipeline import clean, split
from stylo.workdoc import chunker_config_hash

with TemporaryDirectory() as root:
    p = Path(root)
    raw = p / 'raw' / 'alpha'
    raw.mkdir(parents=True)
    (raw / 'work.txt').write_text('Учебный текст проверяет порядок операций. ' * 100)
    cfg = with_overrides(load_config(), {
        'paths.input_raw': str(p / 'raw'), 'paths.input_clean': str(p / 'clean'),
        'paths.data': str(p / 'data'), 'paths.docs': str(p / 'docs'),
        'evaluation.n_jobs': 1,
        'language.spacy_model': 'synthetic_A', 'language.spacy_model_version': 'A',
    })
    original = clean.load_ner
    clean.load_ner = lambda model, fallback: spacy.blank('ru')
    try:
        clean.run(cfg)
    finally:
        clean.load_ner = original
    changed = with_overrides(cfg, {
        'language.spacy_model': 'synthetic_B', 'language.spacy_model_version': 'B',
    })
    split.run(changed)
    snapshot = split.resolve_fragment_snapshot(p / 'data')
    wm = json.loads((snapshot.train_root / 'alpha/work/manifest.json').read_text())
    print(wm['chunker_config_hash'] == chunker_config_hash(changed))  # True
    print(wm['chunker_config_hash'] == chunker_config_hash(cfg))      # False
```

### R6–R8: cache, deployment config и минимальная длина

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import numpy as np
from stylo.features.embeddings import EmbeddingBlock
from stylo.config import load_config, with_overrides
from stylo.report import evidence
from stylo.chunking import CombinedDoc, make_sent_chunks

with TemporaryDirectory() as root:
    p = Path(root)
    a = EmbeddingBlock(max_length=256, cache_dir=p / 'emb')
    a._store('Синтетический текст.', np.array([256., 1.]))
    b = EmbeddingBlock(max_length=512, cache_dir=p / 'emb')
    b._encode_batch = lambda texts: (_ for _ in ()).throw(AssertionError('new encoding'))
    print(b.transform(['Синтетический текст.'], []).toarray())  # старый вектор
    cfg = load_config()
    changed = with_overrides(cfg, {'deployment.expected_bundle_token': 'a' * 32})
    try:
        evidence.publish_prediction(changed, unknown_root=p / 'unknown', report='synthetic',
            bundle_token='a' * 32, bundle_meta={'config_id': evidence._config_id(cfg)})
    except evidence.SectionEvidenceError as error:
        print(error)

class Span:
    def __init__(self, text): self.text = text
    def __len__(self): return len(self.text.split())

doc = CombinedDoc([Span(' '.join(['слово'] * 500)), Span('Конец.')])
print([len(x.split()) for x in make_sent_chunks(doc, size=500, min_size=200)])
```

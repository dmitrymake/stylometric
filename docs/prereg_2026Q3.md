## 1. Кейс «Тарас Бульба 1842»

Стартовое состояние (после аудита извлечения и пересборки таргетов из полных
редакций ФЭБ; docs/cases/taras_hardened/reports/extraction_audit.json):

- strict additions (23 640 слов): moderate, gate 0.8625, p=0.0005, top gogol,
  chunks 14/16, margin CI [0.014007, 0.029963];
- loose additions (24 303 слова): moderate, gate 0.8625, p=0.0005, top gogol,
  chunks 15/17, margin CI [0.012841, 0.030624];
- речь о товариществе: moderate (single-chunk, диагностика);
- extended-панель (Толстой, Лесков, Салтыков-Щедрин): fail gate 0.7515 —
  не интерпретируется.

Пороги статусов заморожены как реализовано в src/stylo/cases/framework.py:
gate work_macro_recall >= 0.80; strong = winner_share >= 0.90 и margin > 0 и
нижняя граница margin CI95 > 0; moderate = winner_share >= 0.65 и margin > 0.
Эти пороги не меняются по итогам прогонов.

Новые панели (спеки добавляются до прогонов):

- suspects: gogol, annenkov_1840s, pushkin, turgenev, dostoevsky
  (+ бинарный gogol vs annenkov_1840s);
- topic_cossack: gogol, somov, narezhny, grebenka;
- sameperiod: gogol, pushkin, sollogub, annenkov_1840s, grebenka;
- period-диагностика: gogol_early vs gogol_late (paths) + pushkin;
- контрольная батарея: (1) held-out работа Анненкова -> annenkov,
  (2) «Шинель» (exclude из анкора) -> gogol, (3) базовый текст 1835 -> gogol,
  (4) held-out работа Пушкина -> pushkin. Порог батареи: 4/4.

Требование к кандидату: >= 2 eligible works и >= 15 000 слов; иначе автор
получает статус documented-but-unmodelled (Прокопович заранее ожидается в этом
статусе; его письма 1843 г. идут отдельным диагностическим target).

Вилка исходов (формулировки заранее):

- Исход A (во всех панелях top=gogol, контрольная батарея 4/4): «Версия о
  чужой руке в крупных добавлениях 1842 года проверена против фактических
  исторических подозреваемых (Анненков; Прокопович — в пределах доступных
  текстов), против казачьей тематической панели и против панели той же эпохи —
  и не поддерживается: крупные добавления идут к Гоголю.» Ограничения: только
  крупные пассажи; точечная правка не исключается; Прокопович напрямую
  немоделируем.
- Исход B (annenkov_1840s стабильно top на добавлениях): публикация только при
  одновременном выполнении: согласие трёх каналов (fw_fixed, Delta-fw, char3 по
  маскированным текстам); 600-словная sensitivity без reversal; strict И loose
  оба не ниже moderate с top=annenkov; контрольная батарея 4/4; регистровый
  контроль (письма/публицистика Гоголя как псевдо-анкор) исключает артефакт
  травелог-регистра. До выполнения всех пяти условий исход B не публикуется.
- Исход C (gate новых панелей < 0.80): панель записывается как negative
  diagnostic, действующий узкий клейм (панель Пушкин/Тургенев/Достоевский)
  сохраняется без повышения статуса.

Метод-репликация: клейм кейса опирается на согласие fw_fixed и Delta-fw;
char3 (по симметрично маскированным текстам) — диагностический канал.
Расхождение каналов публикуется как ограничение, не скрывается.

## 2. CCAT50 (Трек Б)

Протокол заморожен: фиксированный split 50 авторов, train 2500 / test 2500,
метрика top-1. Выбор варианта слияния каналов (равновесный / val-взвешенный /
стекинг) и метода калибровки каналов — только по OOF-матрице train (критерий:
OOF top-1; калибровка — OOF-NLL). Тест считается один раз финальной
конфигурацией.

Пороговые формулировки:

- итог >= 0.78: «численно выше канонического опубликованного максимума
  канонического протокола (Ngram_A 0.767)», с обязательной оговоркой о
  статистической незначимости разницы ~0.01 при n=2500 (биномиальный CI
  ±1.6 п.п.). Слова «SOTA» и «рекорд» не используются.
- итог < 0.78: публикуется фактическое число с формулировкой «на уровне
  канонического максимума при leak-free выборе гиперпараметров».
- Сравнения с 0.832 (протокол 60/20/20+CV) не проводятся. Связка CCAT50 с
  «русским языком» не используется.

## 3. Финальный LOBO со стекингом (Трек А)

Спек `stylo_stack`: inner StratifiedGroupKFold(3) по книгам внутри
train-фолда; режим слияния (стекинг vs равновесный) выбирается по inner-OOF
top-1; метод калибровки (isotonic / Platt / temperature) — по inner-OOF NLL.
Гиперпараметры каналов не свипуются (конфиг заморожен до прогона).

Правило заголовка: если точка top-1 >= 0.905 И нижняя граница book-bootstrap
CI95 >= 0.86 — формулировка «0.9X [95% CI ...] на 43 авторах, leak-free
book-level LOBO»; иначе headline остаётся «≈0.89». Слово «рекорд» не
используется. Прирост stylo_stack против stylo признаётся только если
author-clustered bootstrap CI разницы не пересекает 0; иначе публикуется
«в пределах шума». Целевой ECE после калибровки: <= 0.10.

### Поправка 2026-07-07 (до каких-либо тестовых прогонов stylo_stack)

Замер стоимости (смоук 12 книг: 96.5 мин на 8 воркерах) показал, что полный
LOBO stylo_stack при inner_folds=3 занимает ~27 часов. Конфигурация стека
меняется по времени счёта, не по метрикам: inner_folds 3 -> 2. Никакие
тестовые числа stylo_stack на момент поправки не существуют.

### Поправка 2026-07-08 (статус stylo_stack в релизном контуре)

`stylo_stack` считается явным калибровочным/канальным экспериментом, а не
моделью headline по умолчанию. Обычный финальный `stylo evaluate` запускает
канонический `stylo` и baselines; стек включается только явным spec. Даже при
численном приросте headline меняется только по правилу выше: author-clustered
CI разницы против `stylo` не пересекает 0; иначе результат публикуется как
«в пределах шума» или как калибровочная диагностика.

## 4. RuAA-Bench v1.0 (Трек В)

Состав: PUBLIC_DOMAIN_CLEAR = PUBLIC_DOMAIN минус {gumilev, pilnyak}
(реабилитационное продление, ст. 1281 п. 5 ГК). Книги без установленного
источника исключаются: провенанс обязателен у 100% книг пакета.

Клейм (дословно): «Первый публичный воспроизводимый book-level бенчмарк
атрибуции авторства для русского языка: замороженный leak-free протокол,
манифест с полным SHA256 и официальная baseline-таблица со статистикой
значимости.» Формулировка «первый датасет» не используется. Паспорт бенчмарка
содержит раздел «Смежные ресурсы»: томский корпус (не публичен), proza_ru_hard
(сырой датасет без замороженного протокола), RusProfiling (профилирование),
RuATD (детекция машинного текста).

Изменение состава PD-среза указывается в release notes как юридическое, не как
улучшение метода.
